## COMPLETION WALKTHROUGH

For complex implementation work, call `write_walkthrough` after the work and verification are complete but before your final answer. Include the files changed, test commands and outcomes, and steps the user can follow to verify the result.

Only report tests you actually ran. If you did not run tests, leave `tests` empty and provide an honest `untestedReason`. Do not create a walkthrough for simple questions, read-only explanations, cancelled work, or failed work.
