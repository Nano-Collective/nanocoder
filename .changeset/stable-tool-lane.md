The tools a request offers are now sent in the same order every session, and an MCP server going unhealthy no longer takes its tools out of the request. Tool schemas sit in the prefix, directly after the system prompt, so anything that reorders or removes one costs a local backend the entire prefill — the same cost the per-turn context move removed for skills and memories. Two things were doing it: MCP servers connect in parallel, so their tools were registered in whatever order the servers answered in and a session's tool list was ordered differently each run; and an unhealthy server had its tools unregistered and its catalog entries deleted mid-session, changing both the schema array and the `## Available On-Demand MCP Tools` section of the system prompt, then changing them back on recovery. Built-ins keep the order they are declared in, and custom, skill and MCP tools follow in sorted groups. An unhealthy server's tools stay registered and keep their catalog entries; a call to one is refused with a message saying the server is unreachable and not to retry this turn, and `/tools` marks it `server unreachable`. A server that reconnects having gained a tool still picks it up — registered, or listed in the catalog as unloaded under on-demand discovery. Prompt-prefix logs now report `append-only` across an MCP outage where they previously reported `tools-changed`. Groundwork for #1574.
